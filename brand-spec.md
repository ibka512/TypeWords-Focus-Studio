# TypeWords Focus Studio

## Product direction

TypeWords Focus Studio is a calm, keyboard-first learning workspace. It keeps the
original TypeWords wordmark, content, routes, data, and learning behavior while
replacing the application chrome and visual system.

## Design read

- Artifact: responsive language-learning web application
- Audience: self-directed learners who spend focused sessions at a keyboard
- Visual language: restrained editorial productivity tool
- Mode: redesign-overhaul with protected product and technical contracts
- Visual variance: 4/10 — stable grid with one dominant daily-task composition
- Motion intensity: 3/10 — short state feedback only
- Information density: 6/10 — scannable operational UI with progressive disclosure
- Asset dependence: 2/10 — the interface, type, and real learning data carry the design
- Brand fidelity: 6/10 — preserve the TypeWords wordmark and functional identity

## Protected contracts

- Preserve every existing route, localization key, persistent-state key, analytics
  event, public component prop/event, and learning workflow.
- Keep the official logo assets under `public/imgs/logo/` without redrawing them.
- Do not change local data schemas, FSRS behavior, dictionary resources, or backup
  behavior as part of the visual redesign.

## Visual system

- Canvas: warm mineral grey `#F4F4EF`
- Primary surface: `#FFFFFF`
- Elevated surface: `#FAFAF7`
- Ink: `#18201D`
- Secondary ink: `#65706A`
- Accent: focused indigo `#5B5BD6`
- Supporting success: sage `#4F7A65`
- Borders: cool-grey hairlines with clear dark-mode counterparts
- Display type: local platform sans, tightened and weighted for a tool-like feel
- Word type: local monospace stack for stable character rhythm
- Radius grammar: 10px controls, 16px cards, 24px primary task surface
- Shadow grammar: almost flat; one soft elevation for overlays and the daily task
- Motion: 160–240ms ease-out, no decorative loops, reduced-motion supported

## Interaction principles

1. The next learning action is always visually dominant.
2. Secondary settings stay available without competing with the task.
3. Cards group actions or selectable resources; metrics use alignment and dividers.
4. Desktop uses a stable left rail; mobile uses a bottom navigation dock.
5. Keyboard focus is visible and every icon-only action has an accessible label.
